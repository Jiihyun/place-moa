# 제출용 데크 아웃라인 — 장소모아

심사 3기준(타겟 정의 / 문제 검증 / 해결책 검증)에 맞춘 10슬라이드 골격.
각 슬라이드에 **[증거]** = 어디서 온 숫자·인용인지 표시. 빈칸은 인터뷰 후 채운다.

---

### 1. 표지
- 장소모아 — "릴스로 저장한 맛집, 이번엔 진짜 간다"
- 한 줄: 링크 공유 한 번 → AI가 장소를 지도에 자동 정리.

### 2. 문제 (Hook)
- "인스타 릴스로 맛집 저장, 다들 하죠. 근데 실제로 몇 곳이나 가봤나요?"
- **[증거]** 부검 방치율 __% (저장한 것 중 실제 방문 __%) · "저장한 줄도 몰랐다" 인용 1개
- 흩어짐 → 못 찾음 → 못 감 (무덤) 도식

### 3. 타겟 정의 (심사 ①)
- 초기 유저 1문장: **릴스로 맛집 저장하지만 네이버 지도 북마크는 안 쓰고 DM/캡쳐로 던지는 20~30대**
- **포함/제외 표** (wedge): DM/캡쳐 O · 지도 북마크 X
- **[증거]** wedge율 __% (부검/폼 참가자 중) — "이 중간 집단이 실재한다"

### 4. 시장 (왜 지금)
- **[증거]** 네이버 장소 저장 누적 1년 **2배↑**, 한도 2,000→5,000곳, 저장 탭 신설 (출처 명시)
- → 저장·재방문 행동은 이미 대중적. 시장은 커지는 중.

### 5. 문제 검증 — 인터뷰 (심사 ②)
- 방법: 타겟 __명 인터뷰 + **과거 저장물 __개 부검** (말이 아니라 실제 행동 기록)
- **[증거]** 핵심 3지표:
  - 방치율(무덤율) __%  |  까먹음율 __%  |  놓친-기회율(지금도 가고싶은데 못 감) __%
- **[증거]** 강렬한 인용 2~3개 (그대로)

### 6. 해결책 (제품 데모)
- 3스텝 GIF/스크린샷: ①릴스 공유 → ②AI가 장소 추출 → ③지도에 핀 + 또간집 평가
- 라이브 URL / QR (지금 바로 써볼 수 있음)

### 7. 해결책 검증 — 실사용 (심사 ③)
- 방법: 인터뷰 참가자가 **그 자리서 실제 릴스를 저장** (행동 관찰)
- **[증거]** 저장 성공률 __% · 평균 소요 __초 · "DM보다 쉽다" __/__ 명
- **[증거]** 앱 로그(퍼널): 방문 __ → 저장시도 __ → 저장성공 __ → 공유 __ (`/api/stats`)
- **[증거]** 자가진단 퀴즈(`/quiz`) 결과: 응답 __명, **타겟 유형 비율 __%**(=wedge율 정량), 완료율 __%
- **[증거]** 플랫폼별 사전신청: iOS __명 / 안드 __명 ("관심 규모" — 의도 지표로 명시)

### 8. 경쟁 & 차별화 (선제 방어)
- 쏙핀·네이버 등 존재 → "통증은 검증됨" (오히려 근거)
- 우리 wedge: **"정리 안 하는 게으른 저장자"** 를 정면 겨냥 (쏙핀=범용, 네이버=수동 저장자용)
- 차별점 후보: 공유→담기 바이럴 루프 / 또간집 큐레이션 / 위치 알림

### 9. 정직한 미검증 + 다음 실험
- **H3(모아두면 실제로 간다 = 재방문)는 아직 미검증** — 2일로는 불가.
- 다음 4주: Wizard-of-Oz 리마인드로 "재발견→실제 방문" 전환 측정 (기존 설계 문서 참조).
- → 심사에 "무엇을 모르는지 아는" 팀으로 각인 (가짜 traction보다 신뢰).

### 10. 정리 / Ask
- 3기준 한 줄 요약 + 이번 검증으로 얻은 결론(GO/재검토) + 필요한 것(지원·기간).
